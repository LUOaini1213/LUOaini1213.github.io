2026.08 – 2026.09 开源 · 智驾评测

NAVSIM 能力阶梯 · 开环规划到底卡在哪

10 个 agent · 563 场同一 metric cache · 配对自助 CI

NAVSIM消融置信区间失败归因
  • 问题　分数是被什么卡住的：网络不够大，还是看不见该看的？跑一个基线看不出来。
  • 做法　搭一条阶梯，每一级只多给一样信息（加速度 → 真值框 → 地图中心线 → 人类速度 → 人类轨迹），全部 563/563 跑同一 metric cache，再对每一级增益做配对自助 95% CI。
  • 结论一　恒速的痛点主要是运动学：只加加速度和 command yaw，PDMS 0.233 → 0.580，NC 失败率 39% → 12%。
  • 结论二　给真值检测框补不上差距，给地图才行：DAC 0.737 → 0.950。
  • 结论三　自己训学习型模型做对照：让它画整条线只有 0.527（手写规则 0.730）；改成规则画线、模型只定速，到 0.763，与手写持平、DAC 失败更低。正则化和训更久都把开环 L1 压低了，闭环分数反而变差。
  • 诚实边界　mini 的 64 个 log 里 62 个就是评测 log，学习型 agent 在全量上是污染分；改为把 10 个 agent 全部限制到同一批 held-out 场景（n=135）重算，并把因此不再显著的结论逐条降级为「提示性」。特权 agent 用真值/地图，不可部署。不是 navtest 正式榜。
最想讲的 模仿学得像，不等于开得安全——开环 L1 很低，仍有 90 场被 DAC 乘成 0。

Glass Box · Agent 可观测中间件

TypeScript / Fastify · 12 个测试 · 结果待评审

OpenTelemetryTraceRedaction策略拦截
  • 问题　Agent 跑完只看得到最后输出。中间调了什么工具、哪步失败、花了多少 token、有没有把密钥读出去，全是黑盒。

  • 边界　Playground / Agent CRUD / Codex Runtime / ECS 路径来自官方 starter，我加的是可观测层；单用户 PoC，容器不是多租户隔离。

2026.09 TechJam Track 3 · GPU kernel

Transformer 前向 GPU kernel 优化

13/13 可评形状 PASS · 免费云 GPU · 结果待评审

FlashAttentiontorch.compile数值等价
  • 问题　最狠的一档 seq_len=100000，基线光注意力分数矩阵就要约 20.5 TB 显存——不是快慢问题，是压根跑不起来。
  • 做什么　用 SDPA/FlashAttention 把 O(S²) 换成 O(S) 融合核，再对 100k 那档做批分块写进预分配张量；保留全部基线子模块与参数名，只重写前向，保证权重严格拷贝可比。
  • 结果　13/13 可评形状 PASS，中位加速 2.07×（P100）/ 2.28×（T4），最高 4.00×；100k 那档在 14.6 GB 内跑完。
  • 取舍　fp16 能把中位加速翻到 4.01×，但最差绝对误差已越过 atol=0.002、只靠相对误差分支存活——默认关闭。少一倍加速，换一个不踩线的数。

2026.09 TechJam Track 4 · 对话式搜索

ByteSize · 问够了才推荐

五万件目录 · 0 token / $0 · 结果待评审

信息价值停止后融合排序离线
  • 问题　多轮购物对话里，agent 最容易犯的错是候选池一小就急着推荐。但池子小不等于信息够——可能只是被猜窄了。
  • 做什么　每轮显式判断证据够不够：够就推荐，不够再问一轮。控制器只看场景、已披露槽位和池子大小，从不偷看剩余轮次预算，也不改排序函数。

  • 边界　holdout 与 800 条为自切的 ID 隔离切分，不是官方榜。
